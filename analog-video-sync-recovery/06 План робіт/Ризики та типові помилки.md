# Ризики та типові помилки (чек-лист «де тут легко помилитись»)

## Таймінг
- [ ] **Генерація/вимірювання в перериваннях.** Латентність IRQ 0.5–2 мкс = зруйнована картинка. Тільки PIO/таймери/DMA. (Урок PicoSync: софтверне об'єднання H/V виявилось нестабільним → винесли в залізо.)
- [ ] **Різні тактові домени** для капчера й генератора → повільний дрейф → «пливе» позиція вставленого sync. Один системний лічильник.
- [ ] **Період прибитий до 64.000 мкс.** Дешеві камери не мають кварцу; період може бути 63.9 або 64.2 мкс. Без інтегральної гілки маховик за 100 рядків з'їде на кілька мкс. Обов'язково оцінювати період.
- [ ] **Занадто вузьке вікно** → трекер ігнорує справжні імпульси при джитері камери → фальшивий COAST на хорошому сигналі. Вікно ≥ 3σ джитеру, не менше ±0.5 мкс.
- [ ] **Занадто широке вікно** в LOCKED → шум затягує фазу. Два набори параметрів (search/locked) — не один.
- [ ] **Немає гістерезису** LOCK/UNLOCK → «дрижання» станів, монітор бачить стрибки. Лічильники N_lock, N_unlock ≥ 8.
- [ ] **Парність полів** із пів-рядковим зсувом: помилка → вертикальне дрижання. Тестувати окремо на генераторі.
- [ ] **Хибний V-sync у шумі** перезапускає лічильник рядків → «зрив кадру». V приймати лише у вікні ±3 рядки, поза ним — з подвійним підтвердженням.
- [ ] **Кварц 50 ppm ≈ 3 нс/рядок дрейфу** → за 1 с coasting майже рядок. Це нормально для повної втрати, але **під час часткових пропадань період має бути вже вивченим**. Кварц 10–20 ppm недорогий — взяти.

## Аналог
- [ ] **Рівень вставленого sync не збігається** з вхідним → «сходинки» рівня гасіння → clamp монітора смикає яскравість. Clamp на вході + калібрування ± 20 mV.
- [ ] **Зачепили burst** ключем → колір мерехтить/зникає. Кінець імпульсу ≤ 5.0 мкс від фронту; перевірити на NTSC (burst від 5.3 мкс).
- [ ] **74HC4053 у 75-омному тракті** — високий R_on, послаблення й спотворення. Брати TS5A3159/ADG719 або ставити ключ перед буфером.
- [ ] **Подвійна/відсутня термінація** → 0.5/2 Vpp. Роз'єми з фіксованими 75 Ω на платі.
- [ ] **Немає ФНЧ перед сепаратором** → хрома і ВЧ-шум дають хибні імпульси. 620 Ω/510 pF мінімум.
- [ ] **Діодний clamp «їде» по шуму** → у сильному шумі рівень гасіння плаває саме тоді, коли він найпотрібніший. Keyed back-porch clamp від трекера — план на v2.
- [ ] **Hot-plug LMH1980** «підвішує» вхід — не брати LMH1980, брати LMH1981/EL4583/LM1881.
- [ ] **Живлення від DC-DC** шумить у відео. LDO на аналог, окрема земля-зірка.

## Методологія
- [ ] **Немає bypass** → неможливо чесно порівняти «з/без». Механічний перемикач із першого макета.
- [ ] **Тестувати лише «відходячи з дроном»** — неповторювано. Атенюатор між VTX і VRX.
- [ ] **Один монітор.** Декодери різні (NVP6124-подібні мають content-детектор). Мінімум 2–3 пристрої відображення.
- [ ] **Довіряти EasyCap як еталону** — його декодер теж бланкує. Еталон — осцилограф/логічний аналізатор.
- [ ] **Оптимізувати трекер на залізі** без симулятора — довго і неповторювано. Спочатку CSV з реальних міток + симулятор на ПК (етап 0.5 / 1.4).
- [ ] **Змішати варіанти A/B/C в одному макеті** — незрозуміло, що працює. Один варіант за раз, гіпотези H1/H4 закриваємо перед платою.

## Залишковий фундаментальний ризик
У дуже сильному шумі **вершина sync у вхідному сигналі теж зашумлена** — наш детектор на вході бачить те саме, що й декодер монітора. Наша перевага лише у (а) маховику з вивченим періодом, (б) вікні очікування, (в) вставці ідеального sync. Якщо цього мало — наступний рівень лише на боці приймача (RSSI, diversity, як RapidFIRE/ClearView) або оцифровка з freeze-frame (варіант C).
