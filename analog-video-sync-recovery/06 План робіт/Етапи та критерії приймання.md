# Етапи та критерії приймання

Принцип: **кожен етап закривається вимірюванням**, а не «здається, працює». Наступний етап не починаємо, доки не закрито попередній.

## Етап 0 — Вимірювання і перевірка гіпотез (2–3 дні, без плати)
| # | Завдання | Критерій закриття |
|---|---|---|
| 0.1 | Осцилограми виходу приймача: добрий сигнал / слабкий / без передавача. Зберегти скріни в `attachments/` | Знаємо: амплітуду, рівень гасіння, чи є шум чи «тиша» при втраті, джитер sync |
| 0.2 | Розібрати монітор, ідентифікувати декодер/скейлер, перевірити сервісне меню на «no blue screen» | Фото плати + маркування чипа в [[Відеодекодери моніторів]] |
| 0.3 | **H1**: Pico з pico-pattern генерує чистий PAL sync; через ручний ключ подати монітору «sync + шум від VRX без VTX» | Монітор тримає картинку (сніг) ≥ 1 хв без синього екрана → H1 підтверджено на **нашому** моніторі |
| 0.4 | **H4**: MAX7456/AT7456E в Autosync між VRX і монітором ([[MAX7456 як готовий регенератор]]) | Таблиця: що на VOUT при втраті, чи проходить відео, стрибок фази, час повернення |
| 0.5 | Логер міток часу CSYNC (LM1881 + Pico) під час реальних пропадань → CSV | ≥ 10 хв запису з ≥ 20 подіями пропадання; це вхід для симулятора |

## Етап 1 — Макет варіанту A на макетній платі (1–2 тижні)
| # | Завдання | Критерій |
|---|---|---|
| 1.1 | Блок 1 + Блок 2 + Блок 6 (THS7314, LM1881) наскрізь, без MCU | Критерії приймання Блоків 1, 2, 6 виконані; картинка через макет = картинка напряму |
| 1.2 | Блок 4 (генератор) + Блок 5 (ключ) у free-run на «сіре» відео | Монітор показує стабільне поле від нашого генератора |
| 1.3 | Тест «forced replace 100 %» на чистому сигналі | Картинка не зміщується, колір є, glitch ≤ 20 mV |
| 1.4 | Блок 3 у симуляторі на CSV з 0.5 | ≥ 99.9 % рядків відновлено при 30 % пошкоджених |
| 1.5 | Блок 3 на залізі, повний цикл | Критерії Блоку 3; при вимкненні VTX — сніг, не синій; повернення ≤ 20 ms |

## Етап 2 — Польові випробування макета (1 тиждень)
- Політ/прогулянка з дроном на межі дальності; A/B через bypass; відео з DVR монітора для порівняння.
- Метрика: **час «корисної картинки»** (пілот бачить горизонт/об'єкти) з пристроєм і без, у секундах на 10 подій пропадання.
- Критерій: приріст ≥ 1 с на подію в середньому і жодного погіршення на хорошому сигналі.

## Етап 3 — Плата v1 (2 тижні)
- KiCad, 2 шари, RP2040 + THS7314 + LM1881/LMH1981 + TS5A3159 ×2, роз'єми RCA, bypass-перемикач, живлення 2S–6S.
- Критерій: усі критерії блоків повторені на платі; 3 екземпляри працюють однаково.

## Етап 4 (опційно) — Гібрид з АЦП / варіант C
Лише якщо етап 2 показав, що LM1881-детекція є вузьким місцем. Див. [[Варіант C - повна оцифровка]].

## Стоп-сигнали (коли зупинитись і переглянути план)
- H1 не підтвердилась на нашому моніторі (монітор має content-детектор) → шукати інший монітор або переходити на варіант C з «freeze frame».
- Джитер камери/передавача > ±1 мкс від рядка до рядка → вікно трекера треба робити адаптивним ще на етапі 1.4.
