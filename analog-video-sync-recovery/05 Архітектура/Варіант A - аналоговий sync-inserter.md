# Варіант A — аналоговий sync-inserter з цифровим трекером

**Це основний варіант.** Прямий нащадок «video stabilizer»-схем 1990-х (LM1881 + генератор + ключ), але з мікроконтролерним flywheel-трекером замість тупого таймера.

## Склад
| Блок | Компонент (прототип) | Компонент (плата) |
|---|---|---|
| Вхід | 75 Ω, THS7314 (буфер із clamp, ФНЧ) | те саме або MAX4090 |
| Сепаратор | LM1881 (клон) + 620Ω/510pF | LMH1981 / EL4583 |
| Трекер + генератор | **RP2040** (Pico): PIO для вимірювання фронтів з точністю 8 нс і генерації CSYNC; або STM32G4/H7 (таймери з input capture + DMA) | те саме |
| Ключ | TS5A3159 (SPDT, 1 Ω, ~100 MHz) | TS5A3159 / ADG719 |
| Рівень sync | дільник/ЦАП: −300 mV відносно рівня гасіння виходу | ЦАП MCU + буфер, підлаштування |
| Вихідний драйвер | THS7314 (2×, 75 Ω) або LMH6611 | те саме |
| Індикація | 2 LED (LOCK/COAST), UART-лог | OLED/кнопки за бажанням |

## Часова точність — головне питання
- RP2040 @ 125–133 MHz: крок PIO **8 нс** → джитер вставленого sync ≤ ±8 нс; це на порядок краще потрібних ±100 нс.
- Input capture фронтів CSYNC: PIO або таймер, без переривань у критичному шляху (переривання з латентністю 1–2 мкс тут неприйнятні для генерації; для оцінки положення — теж лише через апаратний timestamp).
- Логіка трекера (PLL, лічильники) працює **на рівні рядка** (64 мкс) — для MCU це вільно: ~8 000 тактів на рядок.

## Чому вставляємо лише sync tip, а не все гасіння
Див. [[Проблема кольорового burst]]. Короткий висновок: якщо ключ активний тільки на 4.7 мкс (+запас), burst і активне відео проходять недоторканими → колір зберігається, поки він є на вході.

## Проблема рівнів (найчастіша помилка в таких схемах)
Вставлений sync має бути на **−300 mV відносно рівня гасіння того ж сигналу**. Рівень гасіння вхідного сигналу «плаває» (AC-зв'язок, шум, AGC приймача). Варіанти:
1. **Clamp на вході** (THS7314 sync-tip clamp або keyed back-porch clamp, керований від трекера) → рівень гасіння фіксований → рівень sync можна задати константою. **Рекомендовано.**
2. Вимірювати рівень гасіння АЦП MCU на back porch кожного рядка та підлаштовувати ЦАП рівня sync — гнучкіше, але складніше.

Помилка рівня на 100 mV з'їдає третину амплітуди sync; більшість декодерів ще тримають lock при амплітуді sync 20–200 % від номіналу (ADV7180: «good Hsync 20…200 % of expected»), але краще бути в ±10 %.

## Джитер ключа та «сходинки»
Перемикання ключа в момент, коли вхідне відео не на рівні гасіння (наприклад, у шумі), дає стрибок. Це нормально — це і є те, що ми хочемо (примусовий рівень). Але **на виході з режиму** (кінець sync) стрибок від −300 mV до шуму може виглядати як «шип» — тому вихідний ФНЧ (THS7314 має вбудований 5-го порядку, ~9 MHz) корисний.

## Захист «не нашкодь»
- У режимі PASS ключ постійно на вході — пристрій = буфер. Якщо MCU завис (watchdog) — ключ за замовчуванням у PASS (підтяжка керуючого піна).
- Bypass-реле/перемичка для порівняння «з пристроєм / без».

## Що потрібно виміряти до розробки плати
- [ ] Що віддає наш приймач при втраті сигналу (шум? нуль? sync залишається?) — осцилограма. [[Тестовий стенд]]
- [ ] Чи тримає **наш** монітор картинку при чистому sync + шумовому відео. Швидкий тест без MCU: генератор PAL-sync (Pico) + ключ вручну. Це гіпотеза H1.
- [ ] Реальна амплітуда/джитер вхідного sync у хороших умовах (щоб задати вікно).
