# Огляд архітектури пристрою

## Принцип
Пристрій — **прозорий аналоговий тракт** із «розумним» перемикачем: 99 % часу він просто пропускає CVBS від приймача до монітора; лише в інтервалі, де **має бути** синхроімпульс, він примусово виводить чистий синхроімпульс (свій або вхідний — залежно від стану).

```
                    ┌───────────────────────────────────────────────────┐
 CVBS від     ──►───┤ Блок 1: вхідне кондиціонування (75Ω, буфер, clamp)│
 приймача           └───────┬───────────────────────────┬───────────────┘
                            │ аналог (без затримки)     │ копія на сепаратор
                            │                           ▼
                            │                 ┌──────────────────────┐
                            │                 │ Блок 2: сепаратор    │ CSYNC, VSYNC, O/E
                            │                 │ (LM1881 / LMH1981)   ├───────────┐
                            │                 └──────────────────────┘           ▼
                            │                                     ┌──────────────────────────┐
                            │                                     │ Блок 3: трекер таймінгу  │
                            │                                     │ flywheel PLL, LOCK/UNLOCK│
                            │                                     │ лічильник рядків 0..624  │
                            │                                     └───────────┬──────────────┘
                            │                                                 ▼
                            │                                     ┌──────────────────────────┐
                            │                                     │ Блок 4: генератор чистого│
                            │                                     │ CSYNC (H, V, eq, serr.)  │
                            │                                     └───────────┬──────────────┘
                            ▼                                                 │ SYNC_GATE, SYNC_LEVEL
                    ┌──────────────────────────────────────────────────────────┴──┐
                    │ Блок 5: аналоговий ключ (SPDT, ~100 MHz): відео ↔ рівень sync│
                    └───────────────────────────────┬────────────────────────────┘
                                                    ▼
                    ┌───────────────────────────────────────────────┐
                    │ Блок 6: вихідний драйвер 75Ω (2×, ФНЧ), DC-рівні│──► CVBS на монітор
                    └───────────────────────────────────────────────┘
                    ┌───────────────────────────────────────────────┐
                    │ Блок 7: індикація стану, налаштування, живлення │
                    └───────────────────────────────────────────────┘
```

Затримка тракту: буфер + ключ + драйвер ≈ **десятки наносекунд**. Це головна перевага над цифровими рішеннями.

## Три варіанти реалізації (оцінюємо всі, будуємо перший)
| | [[Варіант A - аналоговий sync-inserter]] | [[MAX7456 як готовий регенератор]] (варіант B) | [[Варіант C - повна оцифровка]] |
|---|---|---|---|
| Ідея | Сепаратор + MCU/FPGA-трекер + аналоговий ключ | Використати OSD-чип, який має autosync/LOS та власний генератор | АЦП → буфер рядка → ЦАП/кодер |
| Затримка | ~0 (нс) | ~0 (проходить аналогово через чип) | ≥1 рядок … 1 кадр |
| Складність | Середня (один MCU, ~10 компонентів) | Низька (готовий модуль OSD за $3) | Висока (FPGA/швидкий MCU, DDR, ЦАП) |
| Ризик | Джитер ключа, рівні, burst | Чип в internal-sync режимі **може не пропускати відео** (перевірити!), LOS = 32 рядки без гістерезису по фазі | Час/гроші, латентність |
| Гнучкість | Повна (наш алгоритм) | Майже нуль | Повна, плюс «freeze frame», OSD, фільтрація шуму |
| Рекомендація | **Основний шлях** | Швидкий експеримент на етапі 0–1 (день роботи) | Етап «2.0», якщо A працює і захочеться більшого |

## Ключове рішення: що саме замінюємо в сигналі
Три режими роботи ключа (Блок 5), перемикаються трекером:
1. **PASS** (стан LOCKED, вхідний sync у вікні): вихід = вхід. Нічого не чіпаємо, навіть sync (він і так добрий).
2. **REPLACE_SYNC** (LOCKED, але імпульс у вікні не знайдено або спотворений): на інтервалі [t₀ − 0.3 мкс; t₀ + 4.7 + 0.3 мкс] виводимо рівень sync tip (−300 mV), решту рядка — вхід. Burst і активне відео не чіпаються.
3. **COAST** (UNLOCKED після втрати сигналу, маховик): те саме, що 2, для **кожного** рядка + генерований V-sync; активне відео — що є на вході (шум). Тривалість — поки не мине T_coast (напр. 3–5 с) або не з'явиться новий стабільний lock.

Опційно (режим 4, налаштовується): **BLANK_PORCH** — додатково притискати front/back porch до 0 mV, щоб шум у гасінні не збивав clamp монітора. Обережно: back porch містить burst — притискати лише до 5.3 мкс і після 8 мкс від фронту sync, або не чіпати взагалі. Див. [[Проблема кольорового burst]].

## Чому це має «точно спрацювати»
- Кожен блок має самостійний критерій приймання і перевіряється окремо на стенді ([[Етапи та критерії приймання]]).
- Алгоритм трекера — це перевірена десятиліттями flywheel-схема телевізорів ([[Flywheel синхронізація]]), а не винахід.
- Аналоговий тракт не може «зламати» хороший сигнал: у режимі PASS пристрій електрично еквівалентний кабелю з буфером.
- Найризиковіші гіпотези (H1: моніторові досить sync; H4: MAX7456) перевіряються **до** розробки плати — на макетах ([[Етапи та критерії приймання]] етап 0).
