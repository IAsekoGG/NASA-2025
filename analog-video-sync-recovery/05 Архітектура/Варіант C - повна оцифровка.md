# Варіант C — повна оцифровка (АЦП → буфер → ЦАП)

## Ідея
Оцифрувати CVBS (АЦП 8–10 біт, 13.5–27 MSPS), знайти sync **у цифрі** (адаптивний поріг, кореляція з формою імпульсу, вікно очікування), записати рядок у буфер і вивести його заново через ЦАП із **власним ідеальним таймінгом** (це називається line TBC — time base corrector рядкового рівня).

## Що дає понад Варіант A
- Ідеально рівні рядки навіть при джитері входу (TBC-ефект).
- Можна «заморозити» останній хороший кадр або **змішувати** (fade) шумний кадр із попереднім — як RapidFIRE.
- Можна регенерувати burst і навіть перекодувати колір (повний decode → encode).
- Цифрове виявлення sync стійкіше за компаратор LM1881: поріг адаптивний, форма імпульсу перевіряється (ширина ≥ N відліків нижче порогу — патент US6833875).

## Ціна
| Пункт | Наслідок |
|---|---|
| Затримка | мінімум 1 рядок (64 мкс) для line-TBC; 1 поле/кадр (20–40 мс) для frame-freeze/fusion |
| Залізо | FPGA (iCE40UP5K/ECP5/Tang Nano 9K) або MCU з швидким АЦП (RP2350 не має; STM32H7 АЦП до 3.6 MSPS — замало для повного відео, але вистачить для **sync-only** оцифровки на 4–8 MSPS через зовнішній АЦП) + відео-АЦП (ADC08100, AD9280, або декодер TVP5150/ADV7180 з цифровим виходом BT.656) + відеокодер (ADV7391/ADV7393) |
| Складність | Місяці проти тижнів |

## Розумний гібрид (найцікавіший підваріант)
Залишити аналоговий наскрізний тракт (варіант A), але **сепаратор замінити на АЦП 10–20 MSPS + цифровий детектор** у FPGA/MCU. Тоді:
- шлях відео — аналоговий, затримка ~0;
- шлях sync — цифровий, з адаптивним порогом і перевіркою форми;
- це рівно те, що робить блок «HSYNC processor» в ADV7180.
Апаратно: RP2350 з PIO читає паралельний 8-бітний АЦП (ADC08100 за ~$5) на 20 MSPS у DMA — реальні проєкти є (PIO-capture на 20+ MSPS). Це природний **етап 2** після робочого варіанту A.

## Готові цеглини для варіанту C
- Відеодекодери з BT.656: TVP5150/5151 (TI), ADV7180/7182 (ADI) — вони самі роблять flywheel-lock, і мають режими для «noisy video». Але вони **декодують** (YCbCr), а не пропускають CVBS — треба кодер назад.
- Open source: OSSC, GBS-Control (FPGA/ESP32 скейлери), MiSTer analog IO, ld-decode/vhs-decode (софтверні алгоритми пошуку sync у шумі — корисно почитати їх код для вікна очікування та PLL по рядках).
- Див. [[DIY та open-source проєкти]].

## Рішення
Не починати з C. Побудувати A; якщо бракуватиме якості sync-детекції — перейти до гібриду (АЦП замість LM1881), не змінюючи решту.
