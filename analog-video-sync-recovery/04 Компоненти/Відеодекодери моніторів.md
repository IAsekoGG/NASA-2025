# Відеодекодери моніторів — що їм потрібно для lock

> Ми не проєктуємо декодер, але маємо розуміти його «смаки»: наш вихід — його вхід.

| Чип | Де трапляється | Механізм lock | Поведінка при втраті | Джерело |
|---|---|---|---|---|
| **ADV7180/7182** (ADI) | CCTV, вбудовані системи, деякі монітори | Лічильник послідовних «хороших» H-sync (амплітуда 20–200 %, частота ±5 %); FREE_RUN (кілька полів, з урахуванням V) або TIME_WIN (рядок-до-рядка), реєстр 0x51 SRLS; HSYNC/VSYNC processor фільтрує зашумлені sync | IN_LOCK/LOST_LOCK через ~1 с (250 ms у fast-switch); при втраті — «default blue screen» | datasheet; EZ 5356, 11871 |
| **TVP5150/5151** (TI) | дуже поширений | Status reg 0x88: Color/H/V lock біти; «patented technology for locking to weak, noisy, or unstable signals»; INT при зміні статусу | free-run, синій/чорний за налаштуванням | datasheet; E2E 370655 |
| **TW9910/TW2866** (Techwell/Renesas) | реєстратори, монітори | «digital PLL and decision logic… reliable sync detection in stable and unstable signals», режим для non-standard/weak | — | Renesas data short |
| **NVP6124 / RN6752** (Nextchip/Richnex) | AHD/CVBS CCTV | «Robust Sync Detection» (genlock до H, V, subcarrier) **плюс окремий** «Robust No-Video Detection» | може бланкувати навіть при чистому sync — ризик | datasheet (Scribd/alldatasheet) |
| **SAA7113** (NXP) | старі пристрої | I2C, CVBS/S-Video; деталі lock-бітів не отримано | — | Mouser datasheet |
| **Скейлери RTD2660 / Novatek NT68xxx / MStar** | **більшість дешевих FPV-моніторів** | Вбудований CVBS-декодер; datasheet під NDA, деталі невідомі; RTD2660 має налаштовувану заставку «no signal» | заставка/синій екран | BitBuilt форум |

## Що з цього випливає для регенератора
1. **Частота** sync критична (±5 % — це м'яко, але дешеві скейлери можуть бути суворішими; тримаємось ±0.1 % = кварц).
2. **Амплітуда** sync — запас великий (20–200 %), але для «TIME_WIN»-подібних детекторів кожен рядок має мати впізнаваний sync.
3. **Регулярність V-sync** з правильною кількістю рядків у полі — FREE_RUN-тип детекторів рахує рядки між V-sync; «плаваюча» кількість рядків = втрата lock або перемикання стандарту PAL/NTSC.
4. Burst не потрібен для lock, лише для кольору.
5. **Тест на реальних моніторах обов'язковий**: список моніторів/окулярів для перевірки має бути в [[Тестовий стенд]]; якщо в нашому моніторі стоїть скейлер із власним «no-video» детектором — дізнаємось лише експериментально. Розібрати монітор і сфотографувати чип — перший крок етапу 0.

## Як зрозуміти, який чип у моніторі
- Розібрати, сфотографувати плату; маркування на найбільшому QFP/QFN біля входу AV.
- Якщо є UART/сервісне меню — часто там є назва скейлера.
- Teardown-ів FPV-моніторів (Eachine LCD5802D, Feelworld, Foxeer) у відкритому доступі не знайдено — доведеться робити самим і задокументувати тут.
