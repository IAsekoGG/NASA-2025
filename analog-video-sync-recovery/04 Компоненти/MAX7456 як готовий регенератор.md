# MAX7456 / AT7456E як готовий регенератор (варіант B)

> OSD-чип з кожного польотного контролера ($2–5, модулі MinimOSD за $3). Має вбудований сепаратор, clamp, детектор втрати sync і **власний генератор sync**. Питання: чи можна змусити його виконати нашу роботу без жодного MCU-коду?

## Підтверджені факти з datasheet
- Вхід: AC-зв'язок 0.1 µF (обов'язково), clamp прив'язує sync tip до ~550 mV **порядково**.
- Сепаратор виділяє H/V для OSD і для **LOS** (loss of sync).
- **LOS = 1** після **32 рядків поспіль** без sync; **LOS = 0** після 32 рядків поспіль з валідним H-sync. Гістерезис за кількістю, не за фазою.
- Реєстр **VM0 біти [5:4] — Sync Select:** `0x` = **Autosync** (зовнішній sync поки LOS=0, внутрішній коли LOS=1); `10` = External; `11` = Internal.
- Внутрішній генератор працює від кварцу 27 MHz.
- Datasheet Fig. 5: «VOUT, VSYNC, HSYNC timing in NTSC internal sync mode».

## Що НЕ підтверджено (треба перевірити на столі або в повному PDF)
1. **Чи проходить вхідне відео на VOUT в internal-sync режимі?** Логічно — ні: у внутрішньому режимі чип малює OSD на власному фоні (сірий/чорний), бо мультиплексор OSD не має до чого прив'язатись. Тоді при LOS ми отримаємо не «сніг із фрагментами», а порожній екран із чистим sync — монітор не бланкуватиме, але й картинки не буде. Це **суттєво гірше** за наш варіант A, де шумне відео проходить.
2. **Фазова неперервність:** при перемиканні LOS 0→1 внутрішній генератор, ймовірно, стартує з власної фази (free-run від 27 MHz), а не продовжує фазу втраченого зовнішнього sync → монітор побачить стрибок фази на межі, можливо «кадр здригнеться». При 1→0 — ще один стрибок. Для нас це прийнятно (все одно краще синього екрана), але не ідеально.
3. **Затримка VIN→VOUT** — не знайдено; ймовірно десятки–сотні нс (аналоговий шлях через мультиплексор).
4. Поведінка при **частковому** шумі (LOS ще 0, але sync спотворений): чип у external-режимі пропускає вхід як є → нічого не виправляє. Тобто MAX7456 допомагає лише при **повній** втраті на ≥32 рядки, а не при «рваному» sync. Це головне обмеження для FPV.

## План експерименту (етап 0, півдня)
1. Модуль MinimOSD/AT7456E + Arduino/Pico по SPI: записати VM0 = enable OSD, Autosync, PAL.
2. Подати відео з приймача; на осцилографі двоканально VIN і VOUT.
3. Вимкнути передавач. Виміряти: (а) через скільки рядків VOUT переходить на внутрішній sync; (б) чи є на VOUT вхідний шум/відео чи лише фон; (в) стрибок фази H-sync на переході; (г) поведінка монітора.
4. Увімкнути передавач: час повернення, чи є «здригання».
5. Проміжний шум (атенюатор між VTX і VRX): чи виправляє щось MAX7456, поки LOS=0.

## Вердикт (попередній, до тесту)
MAX7456 — швидкий «костиль» проти **повного** синього екрана, корисний як **запасний план і як еталон для порівняння**, але не розв'язує задачу «тримати картинку в шумі», бо (а) в internal-режимі, ймовірно, не пропускає відео, (б) нічого не робить при частково зіпсованому sync. Основний шлях — [[Варіант A - аналоговий sync-inserter]]. Цікавий гібрид: використати MAX7456 лише як **сепаратор + clamp** (виходи HSYNC/VSYNC/LOS), а вставку робити своїм ключем.
