# Структура сигналу CVBS (PAL / NTSC)

> Композитне відео = яскравість + кольорова піднесуча + **синхроімпульси** в одному дроті, 1 Vpp на 75 Ω.
> Наш пристрій працює саме з тією частиною, що нижче рівня чорного: синхроімпульсами.

## Рівні напруги (1 Vpp у навантаження 75 Ω)
| Рівень | PAL | NTSC |
|---|---|---|
| Вершина синхро (sync tip) | −300 mV | −286 mV (−40 IRE) |
| Гасіння (blanking) | 0 mV | 0 mV (0 IRE) |
| Чорний | 0 mV (без setup) | +54 mV (7.5 IRE «setup») |
| Білий | +700 mV | +714 mV (100 IRE) |
| Burst (розмах) | 300 mV p-p | 286 mV p-p (40 IRE) |

Сепаратори синхро (LM1881 тощо) працюють від рівня sync tip: вони «прив'язують» (clamp) вершину синхро і ставлять поріг на ~70 mV вище. Тому все, що шум затягує нижче цього порогу, стає **хибним синхроімпульсом** — це головна проблема ([[Чому монітор втрачає картинку]]).

## Рядок (горизонтальна розгортка)
| Параметр | PAL (625/50) | NTSC (525/60) |
|---|---|---|
| Період рядка H | 64.000 мкс (15.625 kHz) | 63.556 мкс (15.734 kHz) |
| H-sync (ширина) | 4.7 мкс | 4.7 мкс |
| Front porch (перед sync) | 1.65 мкс | 1.5 мкс |
| Back porch (після sync, до відео) | 5.7 мкс | 4.7 мкс |
| Початок burst від переднього фронту sync | 5.6 мкс | 5.3 мкс |
| Burst | 10 ± 1 періодів 4.43361875 MHz (≈2.25 мкс) | 9 періодів 3.579545 MHz (≈2.5 мкс) |
| Активне відео | ≈52 мкс | ≈52.6 мкс |
| Повне гасіння рядка | 12.05 мкс | 10.9 мкс |

```
 <---------------------------- 64 мкс (PAL) ---------------------------->
  front   |  sync  |  back porch (burst)  |        активне відео        |
  1.65мкс |  4.7   |   5.7 мкс  ~~burst~~ |          ~52 мкс            |
 0 mV     |-300 mV |  0 mV                |     0 ... +700 mV           |
```

**Наслідок для нас:** якщо ми замінюємо лише інтервал sync tip (0…4.7 мкс від передбаченого початку) і невеликі поля навколо (≈±0.3 мкс), **burst залишається неушкодженим** → колір зберігається, поки він є у вхідному сигналі. Якщо ж замінити весь інтервал гасіння (12 мкс), burst буде знищено і монітор перейде в ч/б (або втратить color lock). Див. [[Проблема кольорового burst]].

## Поле / кадр (вертикальна розгортка)
| Параметр | PAL | NTSC |
|---|---|---|
| Рядків у кадрі | 625 | 525 |
| Рядків у полі | 312.5 | 262.5 |
| Період поля | 20 ms (50 Hz) | 16.683 ms (59.94 Hz) |
| Період кадру | 40 ms (25 Hz) | 33.367 ms (29.97 Hz) |
| Pre-equalizing імпульси | 5 (2.5 рядка) | 6 (3 рядки) |
| Broad (V-sync, serration) імпульси | 5 (2.5 рядка) | 6 (3 рядки) |
| Post-equalizing імпульси | 5 (2.5 рядка) | 6 (3 рядки) |
| Ширина equalizing імпульсу | 2.35 мкс | 2.3 мкс |
| Ширина broad імпульсу | 27.3 мкс | 27.1 мкс |
| Частота імпульсів у V-інтервалі | 2× рядкова (кожні 32 мкс) | 2× рядкова (кожні 31.78 мкс) |
| Активних рядків | 576 | 480 (486) |

Черезрядковість (interlace): парне і непарне поле відрізняються на **пів-рядка** зсувом V-sync відносно H-sync. Декодер визначає парність поля саме за цим зсувом. Якщо регенерований V-sync поставити «не в ту» половину рядка — картинка почне «дрижати» по вертикалі на 1 рядок або декодер втратить interlace lock. Тому наш генератор має вести лічильник рядків **0…624** з півлінійною точністю.

## Що саме потрібно декодеру монітора
1. **H-sync у кожному рядку** з джитером < ~100–200 нс (інакше «рвана» картинка, але lock тримається).
2. **V-sync** зі впізнаваною структурою (broad-імпульси) з періодом 20/16.68 ms. Багатьом декодерам достатньо «інтегрованого» V-sync (довгі імпульси), equalizing-імпульси — бажані, але не критичні.
3. **Burst** — тільки для кольору. Без burst — ч/б, але lock зберігається (перевірити на конкретному моніторі: [[Відеодекодери моніторів]]).
4. Правильна кількість рядків у полі (декодери мають лічильник рядків і «стандарт-детектор» PAL/NTSC: якщо кількість рядків «пливе», монітор може перемикати стандарт і блимати).

## Що ламає шум радіоканалу
- Шум FM-демодулятора має великий розмах і **симетричний** — «викиди вниз» перетинають поріг сепаратора → хибні H-sync посеред рядка.
- Пропадання сигналу («squelch» у приймачі) → приймач або віддає суцільний шум («сніг»), або взагалі мутить вихід — треба **виміряти** осцилографом, що саме віддає наш приймач ([[Тестовий стенд]]).
- Multipath → фазові стрибки → sync зміщується на ±сотні нс за кілька рядків.
