# Flywheel («маховикова») синхронізація — як це робили телевізори

> Ідея 1950-х, яка досі є основою будь-якого відеодекодера: **не запускати розгортку від кожного синхроімпульсу, а вести власний стабільний генератор і лише злегка підправляти його фазу за середнім положенням багатьох імпульсів.**

## Чому «пряма» синхронізація не працює в шумі
Ранні телевізори запускали рядкову розгортку безпосередньо від сепарованого синхроімпульсу («triggered sync»). У шумі кожен хибний імпульс зривав рядок → картинка «сипалась». Рішення — flywheel sync (patent US2951117 та ін.): 
- власний генератор рядкової частоти (у нас — таймер MCU/FPGA від кварцу);
- **фазовий детектор** порівнює вхідний sync із генератором;
- **ФНЧ (фільтр петлі)** з великою постійною часу (десятки–сотні рядків) усереднює похибку;
- генератор підлаштовується повільно → поодинокі хибні/пропущені імпульси майже не впливають.

Це класична **PLL**, у якій:
- «маховик» = інерція петлі (низька смуга),
- при зникненні входу генератор продовжує працювати з останньою частотою → **coasting** (у нас — «тримати кілька секунд»).

## Три елементи, які додали телевізори, і які нам треба повторити
### 1. Вікно синхронізації (sync gate / window)
Коли петля вже захоплена, фазовий детектор «відкривається» лише у **вузькому вікні** навколо очікуваного моменту sync (наприклад ±2 мкс). Імпульси поза вікном ігноруються повністю. Це різко підвищує завадостійкість: хибний sync посеред рядка просто не бачиться.

### 2. Детектор збігу (coincidence detector) → стан LOCK/UNLOCK
Окрема схема рахує, чи потрапляють вхідні sync у вікно. 
- Багато послідовних збігів → стан **LOCKED**.
- Багато послідовних промахів → стан **UNLOCKED**.
- Потрібен **гістерезис**: у MAX7456, наприклад, LOS ставиться після 32 рядків без sync і знімається після 32 рядків із sync (див. [[MAX7456 як готовий регенератор]]).

### 3. Перемикання постійної часу (search / locked)
- **Search (швидка петля):** велика смуга, широке вікно — швидке захоплення за десятки рядків після появи сигналу.
- **Locked (повільна петля):** мала смуга, вузьке вікно — максимальна стійкість до шуму.
У мікросхемах типу TDA2579 це реалізовано «потрійним джерелом струму» фазового детектора з автоматичним вибором. Класичні VCR-режими додавали третій, середній стан для нестабільних джерел.

## Вертикальна синхронізація
V-sync в телевізорах виділяли **інтегратором** (RC-ланцюжок: тільки довгі broad-імпульси накопичують достатній заряд). Це саме по собі є фільтром шуму. Для «маховика» по вертикалі достатньо:
- рахувати рядки від останнього достовірного V-sync (лічильник 0…624 / 0…524);
- очікувати наступний V-sync у вікні ±кілька рядків;
- якщо V-sync не прийшов — генерувати свій за лічильником (coasting по вертикалі);
- **не** приймати V-sync поза вікном, поки не накопичиться N підтверджень (захист від хибного «кадру» через шум).

## Переклад у цифрову реалізацію (MCU/FPGA)
Замість VCO і RC-фільтра — **числовий керований генератор (NCO)** або таймер із дробовим періодом:

```
period_est   — оцінка періоду рядка (в тактах, з дробовою частиною), старт: 64.000 мкс
phase_next   — прогнозований момент наступного sync
на кожному фронті від сепаратора в момент t:
    if |t - phase_next| < window:            # потрапив у вікно
        err = t - phase_next
        phase_next += period_est + Kp*err    # корекція фази (пропорційна)
        period_est += Ki*err                 # корекція частоти (інтегральна)
        hits++ ; misses = 0
    else: ігнорувати (хибний імпульс)
якщо вікно минуло без імпульсу:
    phase_next += period_est                 # coasting
    misses++ ; hits = 0
LOCK   = hits ≥ N_lock  (напр. 16 рядків)
UNLOCK = misses ≥ N_unlock (напр. 32–64 рядки), тоді window ← широке, Kp/Ki ← швидкі
```

Типові параметри (з практики TV-декодерів, вимагають підбору на стенді):
| Параметр | Search | Locked |
|---|---|---|
| Вікно | ±8…16 мкс | ±1…2 мкс |
| Kp (фаза) | 0.3…0.5 | 0.05…0.1 |
| Ki (частота) | 1/16…1/32 | 1/256…1/1024 |
| Час захоплення | 10–50 рядків | — |
| Дрейф у coasting | — | визначається кварцом: 50 ppm → 3.2 нс/рядок, за 1 с (15 625 рядків) — ~50 мкс, тобто майже рядок! |

**Важливий висновок про coasting:** без корекції частоти дрейф за секунду може досягти цілого рядка. Але це не страшно: коли сигналу немає, глядач бачить шум; коли сигнал повертається, петля в search-режимі перехоплює фазу за десятки рядків (< 5 ms). Критично лише те, що **під час часткових пропадань** (десятки–сотні рядків) оцінка періоду має бути точною — тому інтегральна гілка петлі повинна встигнути «вивчити» реальний період передавача, поки сигнал добрий.
